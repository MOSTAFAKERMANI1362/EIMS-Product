# جمع‌بندی موج ۴ بازیابی P1

این موج فقط مسیر منطقی G03 را تکمیل می‌کند و به‌معنای فعال‌سازی Pilot واقعی نیست.

در این موج دو فرمان `needs.submit-g03` و `needs.g03-decision` از نظر Mutation به قرارداد اجرایی متصل می‌شوند. وضعیت پرونده، نتیجه بازبینی، مسیر کار و نام رویداد توسط سرور محاسبه می‌شوند و مقادیر مشابهی که از سمت کاربر ارسال شوند معتبر نیستند.

نقش مسیر کار (`WorkRoutingRole`) صرفاً مشخص می‌کند کار بعدی باید به چه نوع کارتابلی هدایت شود و هیچ دسترسی امنیتی، Role Assignment یا Windows Claim ایجاد نمی‌کند.

برای APPROVE و RETURN یک سابقه تصمیم G03 به‌صورت غیرقابل‌جایگزینی ثبت می‌شود. اطلاعات هویتی تصمیم‌گیرنده، Assignment، نسخه پرونده، زمان و Correlation توسط سرور ثبت می‌شوند. در RETURN، توضیح بازگشت در سابقه تصمیم نگهداری می‌شود ولی وارد Event خروجی نمی‌شود.

P2 در این موج State + Decision + Audit + Outbox + Idempotency را در یک مرز تراکنشی منطقی نگه می‌دارد و تست Rollback برای هر مرحله دارد.

محدوده ایمنی حفظ شده است: P5 همچنان Fail-Closed است، Oracle واقعی متصل نشده، Windows Domain واقعی اثبات نشده و فایل مبنای `EIMS_v6.360_WORKLIST_UX_ROLE_SELECTOR_CLEANUP.html` هیچ تغییری نمی‌کند.
